# Newsjack-shaped fixture discovery

Vision check: **Aligns with constraints.** Relevant `VISION.md` sections: "Evidence comes before a score", "Uncertainty must be visible", and "Privacy is the default architecture". This slice maps fixture evidence into `story-discovery.v1`. It does not score outlets, fetch live sources, or enable public display.

Related to #118. Issue #118 stays open.

## What this slice proves with fixtures

`media-lens/worker/discovery/search-provider.js` defines a provider-neutral hit (`title`, `url`, `outlet`, optional `author`, `published_at` or null). Only `fixture` is implemented (`IMPLEMENTED_SEARCH_PROVIDER_MODES`). `host_web_search`, `rss_atom`, and `medialyst` are listed in `PLANNED_SEARCH_PROVIDER_MODES` with status `planned_not_implemented`. For `host_web_search` and `rss_atom`, `createSearchProvider({ mode })`, `createHostWebSearchProvider`, and `createRssAtomSearchProvider` throw `NOT_IMPLEMENTED` before any request. For `medialyst`, `createSearchProvider` returns the deferred Medialyst provider: it refuses credential fields, and its `search` rejects with `NOT_IMPLEMENTED` before any request. An unknown or non-string mode throws `UNKNOWN_SEARCH_PROVIDER_MODE`. `mapNewsjackEvidenceToStoryDiscovery` also refuses a planned `providerMode`, so mapped output cannot be labeled as a host-search, RSS/Atom, or Medialyst result. It accepts only `data_origin` `fixture` or `newsjack_artifacts`, `freshness_grade` `fixture` or `unknown`, and a `provider_id` that is one of the adapter's own values: `fixture:newsjack_shaped`, `newsjack:artifacts`, or `newsjack:disabled`. Other values throw `INVALID_DISCOVERY_LABEL`, so a label such as `newsjack:medialyst` cannot suggest a planned source. The default-off approved-feed client in `discover.js` (PR #155) is a separate path and is not the `rss_atom` search provider. Nothing here reads environment variables or calls a network.

`mapNewsjackEvidenceToStoryDiscovery` stamps `retrieved_at` from the caller. It copies `published_at` only when the value is a UTC ISO timestamp for a real date. An impossible date such as `2026-02-30T12:00:00Z` is refused, not rolled over. Otherwise the member keeps `published_at: null`. The same rule applies to `retrieved_at` and window times. A window is copied only as `start`, `end`, and `hours`, with `start` no later than `end` and 0 < `hours` <= 8784. Any other window is treated as missing, so the result abstains with `window_missing`. The fixture and artifact adapters fall back to the caller's window when the file's window is not valid.

A stated `source_id` is kept only when it is a short opaque token (`[A-Za-z0-9][A-Za-z0-9:_.-]{0,79}`) that does not read as a URL, as defined below. Otherwise the member gets `newsjack:<outlet slug>`. A stated `cluster_id` follows the same rule (up to 120 characters). Otherwise the cluster gets a derived id. Invisible format characters are removed from outlet names. An outlet name with no letter or digit, or one that reads as a URL, counts as missing, so the member is dropped as incomplete. Reads as a URL means it contains `://`, starts with `//`, or starts with `http:`, `https:`, `ftp:`, `ws:`, `wss:`, `javascript:`, `data:`, `vbscript:`, `file:`, `mailto:`, or `blob:`. Titles are display text, never links, and are cut to 300 characters. `coverage_gap` stays `null`. `frames` stays `[]`. `privacy.jev_used` and `privacy.full_text_persisted` stay false.

Cluster basis for this path is `newsjack_cluster_same_public_event`. Newsjack `surfaced` becomes `same_story` with `labeling_basis` `newsjack_relation_surfaced`. `independent_reporting` is used only when `same_story_assessment` is `same_story` and at least two distinct outlets have a qualifying member. A qualifying member is one that will be shown: it has an outlet, a title, and a public `https` URL, and it was not dropped. Its URL must also be a dated non-wire origin URL, its Newsjack relation must be `surfaced`, `same_story`, or absent, and it must not be labeled syndicated or uncertain. No record in the group may give the same URL any other relation (for example `syndicated`, `unclear`, or `different_story`), so conflicting relations do not depend on record order. The first record at a URL still decides that URL's label, so a placeholder-named copy listed first keeps a later named copy of the same URL from qualifying. That can only lower the count. Its outlet must not be a placeholder: `unknown`, `unknown outlet`, `unknown source`, `unknown publisher`, `n/a`, `na`, `none`, `null`, `undefined`, `anonymous`, `not available`, or `not applicable`, ignoring case and surrounding punctuation. A placeholder is shown as given but supplies no outlet. A dropped record, or a record with any other relation, cannot supply the second outlet.

Outlet identity is transitive. Every kept member and every dropped record contributes identity keys: its normalized outlet name, the name's letters and digits after NFKC normalization (so spacing, punctuation, invisible characters, fullwidth forms, and non-Latin spacing do not split an outlet), its registrable domain when its URL is a public `https` URL, and a stated `source_id`. A placeholder outlet name contributes no name keys. Records that share any key are one outlet, and so are records linked through a chain of shared keys. Dropped records take part because they can only join outlets, which lowers the independent count and never raises it. The domain of a wire, press-release, or partner republication host (for example `prnewswire.com` or `yahoo.com`) is not an identity key, because those hosts carry many outlets' copy. That decision uses the host only, so a path such as `/statement` on an outlet's own site does not change it. Aliases that share no key are not detected. For example, `BBC News` on `bbc.com` and `BBC` on `bbc.co.uk` count as two outlets. There is no alias or ownership registry on this path, so the independent count is a heuristic. Undetected aliases can overcount, and the joins above can undercount. It is not a verified count of distinct outlets.

Only the first qualifying URL for each outlet is labeled independent (basis `newsjack_origin_distinct_independent_outlets`), so `independent_reporting` has one row per outlet and `independent_outlet_count` equals that row count. Extra qualifying URLs from an outlet already counted stay `same_story` with basis `same_outlet_additional_url`. Two URLs from one outlet, an alias name linked by domain or `source_id`, a `different_story` assessment, a wire or syndicated source, or a missing or unknown outlet do not grant independence. `validateStoryDiscovery` rejects a cluster whose independent rows repeat an outlet name or host. Wire, press-release, and partner URLs use `syndicated` / `wire_press_release_or_partner_url`. A repeated canonical URL uses `syndicated` / `same_canonical_url`. An explicit Newsjack `syndicated` relation uses `newsjack_relation_syndicated`. Any origin assessment other than `same_story` stays `same_story` / `newsjack_origin_uncertain`. A Newsjack `different_story` relation is checked before the wire, partner, and repeated-URL rules, so that record is dropped and counted as `different_story` rather than shown as syndicated.

Only public `https` URLs become `canonical_url` links. `classifySourceUrl` uses the worker's `parseArticleUrl` policy, which refuses userinfo, loopback, private, link-local, metadata, and other non-public IP literals (including exotic IPv4 forms), single-label hosts, `localhost`, `*.local`, and the exact metadata hostnames. It also refuses names under the suffixes in `NON_PUBLIC_HOST_SUFFIXES`: `.internal`, `.arpa` (including `.home.arpa`), `.localdomain`, `.lan`, `.intranet`, `.corp`, `.private`, `.home`, `.svc`, `.alt`, `.test`, `.invalid`, `.onion`, `.consul`, `.default`, the cloud metadata host `metadata.tencentyun.com`, and the wildcard loopback or private DNS services `.nip.io`, `.sslip.io`, `.xip.io`, `.localtest.me`, `.lvh.me`, `.traefik.me`, `.backname.io`, `.1u.ms`, `.rbndr.us`, `.vcap.me`, `.local.gd`, and `.localhost.direct`. `.example` stays allowed because it is documentation-only and the fixtures use it. These URLs are never fetched on this path. A refused URL drops the member, so it cannot appear as a link. This is a name check, not DNS resolution. A public-looking name that resolves to a private address, including wildcard DNS services not on the list, is not detected here. It is safe on this path only because nothing is fetched. Any later path that fetches a URL needs connect-time address pinning like the analyzer's article fetch.

Every dropped member is counted on the `sources_checked` row: `rejected_incomplete`, `rejected_non_https_url`, `rejected_non_public_url`, `rejected_different_story`, and `rejected_total`. `rejected_members` lists up to 200 drops with `cluster_id`, `group_index`, `reason`, and `outlet`. `cluster_id` is the stated id, or the id the cluster was built with, or null for an unnamed group whose records were all dropped. The counters keep counting past 200. It lists no URL, because a refused URL may be non-public.

`createNewsjackAdapter(...).discoverStoryDocument` reads fixture JSON or an operator artifact directory (`clustered_candidates.json` or `cluster.json`, plus `origin_findings.json` or `story_origin.json`). A missing directory, a missing `artifactsDir`, or a failed directory read returns `status: abstain`, `reason: artifacts_unavailable`, and `sources_checked[].outcome: failed` with a non-null `error`. A readable directory with no matching artifact files uses `outcome: artifacts_read`, `error: null`, and `reason: no_usable_members`. A matching artifact or fixture path that is not a regular file (a directory, symlink, or FIFO) or is larger than 10 MiB returns `error: artifact_not_regular_file` or `artifact_too_large` without being opened. A file that is not valid JSON, has an unexpected top-level type, has none or more than one of the `clusters`, `members`, and `cluster` keys, has a `clusters` field that is not an array, has a `cluster` field that is neither an array nor an object, or has a group without a `members` array returns `error: artifact_json_invalid` or `artifact_shape_invalid`. A top-level array in a cluster artifact is read as a list of groups, so a bare list of member records is also refused. All of these return `status: abstain`, `reason: artifacts_invalid`, `outcome: failed`, and `error_file`. A parse problem never escapes as an exception. Individual member records that are not objects are counted as incomplete. A direct call to the mapper with `hits` that are not an array, or `clusters` that are not an array of objects with `members` arrays, abstains with `artifacts_invalid` and `error: evidence_shape_invalid`. The `disabled` mode, and `fixture` mode with no `fixtureId` or `fixtureDir`, return `status: not_live` with `reason` `discovery_disabled` or `fixture_not_configured` and `outcome: not_checked`, because nothing was read. `cli` mode still throws. `getStoryContext` is unchanged. `GET /stories` is unchanged and stays default-off.

## Still unverified (needs a live provider and a rights decision)

- Host web search and RSS/Atom search are not implemented. Their modes are planned only and fail with `NOT_IMPLEMENTED`. No search was run and no feed was fetched.
- Medialyst account, terms, credentials, SDK, and credit spend are not implemented.
- Whether Media Lens may store or show third-party titles, canonical URLs, and publication times from host search or named feeds.
- Real Newsjack `published_at` recovery, cluster quality, and origin corroboration on live pages.
- `data_origin: "newsjack_artifacts"` is emitted for the artifact read path. The story-discovery validator allows it today because it does not enumerate `data_origin`. Treating it as a production source label still needs an owner note.
- Public `/stories` display, source approval, retention of `latestDiscovery`, and ml-jev proxying. Those remain the decisions in `docs/media-lens-story-discovery-owner-decisions.md`.

Do not describe fixture passes as live coverage or as Medialyst-grade freshness.
