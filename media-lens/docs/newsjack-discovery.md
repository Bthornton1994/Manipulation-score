# Newsjack discovery integration

Related to #118. Issue #118 stays open.

Vision check: **Aligns with constraints.** Relevant `VISION.md` sections: "Evidence comes before a score", "Uncertainty must be visible", "Privacy is the default architecture", "Analyze communication, not identity", and "Misuse resistance is a product requirement". Nothing here scores an outlet or a person, runs a live search, or shows coverage publicly. The vision is silent on third-party news vendors and discovery tooling; `.cursor/rules/agent-tooling.mdc` governs the tooling side (pinned revision, sandboxed test, repository-owned contract, removable adapter) and authorizes no installs.

Media Lens works with Newsjack (https://github.com/elvisun/newsjack, MIT, Copyright (c) 2026 Elvis Sun). License, trademark, and attribution: `docs/NEWSJACK-LICENSE.md`.

## Decision

Newsjack is integrated as an **operator-run component that emits a versioned artifact Media Lens owns**. The operator tool reuses the mechanics of an isolated sibling process, but it lives outside the worker and the worker never imports it.

| Model | Verdict | Why |
| --- | --- | --- |
| Pinned package or dependency | Rejected | Newsjack is a Go CLI, not a library. The npm package is a wrapper around a native binary, so it would be the worker's first dependency and would put an executable beside the public worker. Go import is not possible: the module lives in `apps/cli`, needs Go 1.26, and has no `apps/cli/vX` tags. |
| Pinned git submodule | Rejected | It would pull about 4,300 files (about 4,000 of them eval data, including third-party headlines) and trademarked brand assets, and building needs Go 1.26, which CI does not have. A submodule gives source, not isolation. The commit is pinned in code instead. |
| Isolated sibling process spawned by the worker | Rejected for the worker | Technically feasible (one static binary; `cluster` and `origin-apply` run headless). But auto-update runs before those commands by default, the CLI reads `.env` files and credentials, it has no process-level timeout, and it needs OS-level isolation. Spawning it from the worker stays a non-goal. |
| Operator-run Newsjack emitting versioned artifacts | **Chosen** | Only a file boundary reaches Media Lens. The operator tool runs a pinned binary with strict process limits, validates every output against the pinned shapes, and writes `media-lens.newsjack-capture.v1`. Media Lens converts only a valid capture into `story-discovery.v1`. |

The worker is unchanged except for removals: live `/analyze` reads no Newsjack output (the adapter is `disabled` in live mode), the adapter keeps only `fixture` and `disabled`, and the removed `artifacts` mode's environment variable and `/health` field are gone. On `main` before this change, a live worker with `MEDIA_LENS_NEWSJACK_ARTIFACTS_DIR` set ran an unguarded reader after Jev on `/analyze`; a malformed file returned `500` and the Jev calls already made were not counted in the budget. `tests/media-lens-newsjack-boundary.test.js` covers the fixed behavior.

## What upstream Newsjack can do without Medialyst

Reviewed from source at v0.1.19 (`bdb41b8d1f9a9e27221cc86102cbfe1a748fc123`) and at `main` `092d882fc69912622f620c50eb493afe625f99dc`, which differs only in Medialyst OAuth scope handling. Nothing here is from documentation alone.

- **News search is Medialyst only as shipped.** The CLI's only article search is a `POST` to `{base}{path}` with a bearer token, where `base` is `NEWSJACK_MEDIALYST_API_BASE`, then `MEDIALYST_API_BASE`, then `https://medialyst.ai/api`, and `path` is `MEDIALYST_NEWS_PATH` or `/v1/news/search`. The token is an OAuth grant or an API key (only `auth set-medialyst` checks the `mlst_` prefix; the environment key is not checked). The response parser accepts any JSON with an `items`, `results`, `news`, or `organic` array, so the endpoint could technically point at another compatible service. That is an upstream seam, not an approved provider: the request body is Serper-style (`gl`, `hl`, `tbs`), and nothing else is shipped or documented. Without a credential, `news_search` is dropped before collection and recorded as `unavailable`, and a query run whose requested sources are all unavailable exits with "No requested sources are available".
- **Relative provider dates become clock estimates.** Upstream passes ISO-like dates through unchanged, turns "N hours ago" into the current time minus N hours with nanosecond digits, and reformats HTTP dates to UTC with nanosecond digits when present. Media Lens accepts at most millisecond precision, so those estimates are almost always dropped as `published_at_precision`. Go trims trailing zeros, so an estimate that happens to land on a whole millisecond (about one in a million) passes as a provider time; it is still labeled unverified. A live capture that mostly carried relative dates would convert to few or no members. This is intended: an estimate is not a publication time.
- **What still works without Medialyst is not news search.** Fixed RSS/Atom feeds the operator lists (no query filter; RSS 2.0 `pubDate` is never read at the pinned commit), Reddit and Hacker News query search (forums, not outlets), and X with a paid token (synthetic search URLs and fetch-time dates).
- **"Host web search" is not code.** It exists only as prose in Newsjack's agent skills, for an LLM agent to perform with its own tools.
- **Origin evidence is written by an LLM agent** following the story-origin-check skill, which tells the agent to fetch article pages. `origin-apply` only checks structure and computes freshness from the agent's timestamps, or from a provider-reported detector time (`detector_timestamp_fallback`) in one narrow case: the agent says `same_story`, gives only a date on the boundary day and no precise timestamp, and an article-kind evidence item has a time on that same UTC day (with none before the cutoff). No corroboration is required then; otherwise the status is `unverified_boundary`. Its corroboration gate is weaker than the skill describes.
- **Grouping is a deterministic text-similarity heuristic in two stages.** Inside one signal, the detector merges evidence items that share an exact URL or whose title, snippet, and X metadata text reach a Jaccard similarity of 0.32 with the group. So two articles with no title words in common can be one signal because their snippets overlap. The `cluster` step then merges signals that share a normalized URL or have title overlap of at least 0.6 with at least two shared significant tokens. The capture drops snippets, so the first stage cannot be inspected downstream.
- **Provenance is thin**: no per-item retrieval time, no search-window object, no tool version, and no per-member relation in any output. The client profile is copied into every artifact.

**Missing transport:** a query-based news-article search provider with an owner-approved account, terms, credential storage, spend, and rights to store and show titles, URLs, and times. This change does not fake one. `host_web_search`, `rss_atom`, and `medialyst` stay `planned_not_implemented` in `media-lens/worker/discovery/search-provider.js`, and `SEARCH_PROVIDER_MODE_STATUS.medialyst` is the single approval point the runner and converter consult. A later approved provider plugs in there, or as its own `SearchProvider` whose normalizer reuses `classifySourceUrl`, `outletText`, and `parseProviderTimestamp`.

## Pin and supply chain

`media-lens/worker/discovery/newsjack-pin.js` is the single source of truth: v0.1.19, commit `bdb41b8d1f9a9e27221cc86102cbfe1a748fc123`, tag object `8c20b879186363a939b1c4a7b626107d7df84c58` (annotated, unsigned), the LICENSE and TRADEMARK blobs, the blob of every upstream file whose output shape or process behavior the Media Lens rules encode, and a per-platform binary sha256.

Tags are unsigned and can be moved, release assets can be re-cut, `checksums.txt` comes from the same origin as the binaries, tarballs are not byte-reproducible, and the version string does not identify the commit. So only the executed file's own sha256 identifies what ran. **Both binary hashes are null**, so no real binary can run through the tool until the owner records one in a reviewed change. Acceptable ways to obtain a binary to hash:

- **Source build** from the pinned commit with an exact Go 1.26 patch release: `CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags "-s -w -X main.version=v0.1.19" ./cmd/newsjack` in `apps/cli`. Record the sha256 and the Go version.
- **Release asset or npm platform package** at exact version 0.1.19, recorded only if it matches `checksums.txt` and a second, independent source (for example verified npm provenance, or a source build).

Install it outside `$NEWSJACK_HOME/bin`. The reviewed files include the emitters of every output the rules check and the files that decide credentials and dotenv (`auth.go`, `auth_oauth.go`), the Medialyst endpoint (`api_commands.go`), the store (`detector_store.go`), the binary location lock (`bundle.go`), defaults (`config.go`), null-versus-string output (`doctor.go`), `--topic` parsing (`flags.go`), exit codes (`usage.go`), and story-size score extraction for the representative choice plus the story-recall queue floors (`detector_recall.go`). Upgrades are one reviewed change: diff the reviewed files and `go.mod`/`go.sum` between the old and new commit, check for new files that change process or network behavior, recheck auto-update, dotenv, and proxy behavior, update the pin and reset the binary hashes to null, update the raw rules and fixtures together (`tests/media-lens-newsjack-discovery.test.js` fails if the committed capture example drifts), and run the suite on Node 20 and 22. Captures made under an old pin are refused (`pin_mismatch`).

## The operator tool

`node scripts/newsjack-capture.js run --binary <abs path> --query "<public topic>" --out-dir <abs dir>` calls `runNewsjackCapture` in `media-lens/tools/newsjack-runner.js`. It is not a route, is not deployed with the worker, and is not run in CI with a real binary. In order, failing closed:

1. **Request policy.** One query of 3 to 120 characters and at most 12 words, refusing control characters, a leading `-`, `@`, URLs, `www.`, and runs of six or more digits. `--max-age-hours` 1 to 48 (default 24), `--lookback-days` 1 to 7, `--depth quick|default`, `--limit` 1 to 50. The output directory and `--work-root` (default: the system temp directory) must be existing absolute directories, not symlinks, and outside the repository. `--origin-findings` must be a regular file of at most 5 MiB. It, the binary, the private copy at each re-hash, and any existing output file are read without following a symlink and without blocking on a FIFO swapped in after a check.
2. **Mode gate.** `--live` is refused with `no_approved_transport` while Medialyst is not implemented, and with `live_credentials_not_supported` after that, because no credential is ever passed to the child.
3. **Host gates.** Refused when running as root (`running_as_root`) or when the worker's secrets file is readable (`worker_secrets_readable`).
4. **Binary gate.** The operator's file is copied into a private `0700` directory and executed only if the copy's sha256 equals the pinned hash (`binary_hash_unrecorded` today). The copy is hashed again before every step, so a file rewritten between steps (by anything running as the same user, including the child) stops the run with `binary_hash_mismatch`. A rewrite in the instant between a hash and an exec is not detectable this way; that needs a separate user or container. `PATH` is never searched.
5. **Execution.** Only `version`, `detector run --mock --sources=news_search --no-x-news --no-x-trends --no-profile-feeds ... --topic=<query>`, `cluster`, and (with `--origin-findings`) `origin-apply --allow-missing`. Never `--save`, `--profile`, feed flags, `--run-time`, `update`, `login`, `setup`, `monitor`, `news`, or `coarse-filter`. Each child gets exactly this environment and nothing inherited: private `HOME`, `NEWSJACK_HOME`, `NEWSJACK_ROOT`, `NEWSJACK_WORKDIR`, and `NEWSJACK_STORE`; `NEWSJACK_IGNORE_DOTENV=1`; auto-update locked five ways (`NEWSJACK_AUTO_UPDATE=0`, `NEWSJACK_NO_AUTO_UPDATE=1`, the recursion guard, the npm distribution marker, and a binary outside `$NEWSJACK_HOME/bin`); an empty `PATH`; and all proxy variables set to a closed local port. Each step has a wall-clock limit and a 10 MiB stdout cap. On a limit or an abort the runner sends `SIGTERM` and then `SIGKILL` to the whole process group once, and stops waiting after a hard deadline even if a descendant left the group and still holds the output pipe. An abort that arrives before or between steps stops the run before the next step, and the CLI turns `SIGINT`, `SIGTERM`, and `SIGHUP` into that abort, including when a signal repeats. A `SIGKILL` of the operator's own process cannot be handled; a leftover private directory then stays in the work root. stderr is counted, never read or kept.
6. **Validation and output.** Every output is checked against the pinned shapes (`media-lens/tools/newsjack-raw.js`), including cross-file binding; output nested too deeply to compare is a validation failure (`artifact_structure_invalid`, exit 5), not a crash. A capture is projected, validated, converted, and checked with `validateStoryDiscovery`. The output directory is checked again (still a directory, not a symlink, same real path; otherwise `out_dir_changed`), then each file is written to a private temp file with mode `0600` and hard-linked into place, so an existing file, or one that appears meanwhile, is never replaced (`output_collision`); identical content is a no-op. The temporary directory is removed on every path. Output is a code-only summary; queries, titles, stderr, and paths are never printed.

`node scripts/newsjack-capture.js convert <capture.json>` converts a capture file offline. Exit codes: 0 ok, 1 convert abstained, 2 usage, 3 refused, 4 process failure, 5 validation failure, 6 write failure.

This is not a sandbox. Before any live use the owner still needs a dedicated user, egress rules, and preferably a container, on a host that is not `ml-jev`.

## The capture contract

`media-lens/schema/newsjack-capture.js` defines `media-lens.newsjack-capture.v1`. It is strict at every level (unknown keys are refused), and `capture_id` is the sha256 of the canonical JSON of everything else. It records the pinned tool identity and binary hash, the runner mode (`fixture`, `mock`, or `live`), the request, the runner's own start and exit time for each step, Newsjack's detector clock, selection counts (scored, emitted, hygiene rejects, truncated evidence), per-source status with a reduced error class, signals with only `source`, `title`, `url`, `container`, `published_at`, and a copied-snippet flag, the clustering groups, and optional origin claims. When the title is a copied snippet, the title is stored empty. A container over 300 or a `published_at` over 64 UTF-16 units is stored as null, and a URL over 2,048 as an empty string (the converter counts it as `incomplete`), rather than cut, so a cut can never turn a rejected value into an accepted one; titles are cut at 1,000 UTF-16 units without splitting a character. Runner step times must fall between 2020 and 2100; origin-claim times are agent text, checked for form and calendar validity but not range. A source status must agree with its own flags the way Newsjack derives it (for example `used` means requested, a count above zero, and no error class), evidence of a kind needs a status of `used` or `partial_error` with a count at least as large, the signal count may not exceed `limit`, and an origin claim's freshness window must end at Newsjack's run clock and span exactly `max_age_hours`. Unknown keys are reported by position (`$.sources.*`), never by their text, and JSON nested too deeply to check is refused as `capture_structure_invalid` instead of throwing. Client profile data, excerpts, authors, engagement, raw error text, stores, and agent rationale are never written.

## Conversion into story-discovery.v1

`captureToStoryDiscovery(capture, { now })` in `media-lens/worker/discovery/newsjack-discovery.js` is pure. Nothing is invented:

| story-discovery.v1 | Source | Basis |
| --- | --- | --- |
| `retrieved_at`, every member's `retrieved_at`, `window.end` | runner's clock when the detector process exited | `runner_observed_detector_exit_upper_bound`; Newsjack has no per-item time |
| `window` | `max_age_hours` before `retrieved_at` | `media_lens_published_at_filter_from_max_age_hours`; undated and older items are excluded |
| `provenance.retrieval_interval` | runner's clock when the detector process started and exited | `runner_observed_detector_start_and_exit`; Newsjack's own clock is kept separately as `newsjack_generated_at` |
| `clusters[].cluster_id` | Newsjack's representative signal id | `newsjack_detector_text_similarity_and_cluster_overlap`, with `cluster_params`, a `grouping_note` describing both stages, and a `same_story_note` that similar text is not independent reporting |
| member `outlet` | evidence `container` | provider-reported publication name as display text (NFKC-folded, invisible characters removed), cut to 200 characters before it is checked; URL-like (including `tel:` and `about:`), email-like, host-like (a dotted name with a path or port, any name with a port, `www.`, a dotted, hex, or bracketed IP address with an optional zone, port, or path, or a non-public name such as `localhost`, `metadata`, `*.local`, or `*.internal`, also with a trailing dot), path-like, or empty names drop the item; a bare public domain such as "Reuters.com" and a plain number such as "1843" are kept; other schemes (for example `intent:`) are not recognized |
| member `article_title` | evidence `title` | display text: lone surrogate halves are removed first, so nothing removed later can rejoin them; control characters and blank-looking letters become spaces; other default-ignorable characters (format characters, bidi overrides, variation selectors, joiners, tag characters) are removed without splitting a word; cut to 300 characters with no marker; a title of only punctuation or combining marks is not refused |
| member `canonical_url` | evidence `url` | public `https` only, never fetched; a fixed list of common forum, social, video, short-link, search, and news-aggregator hosts (`NON_OUTLET_HOSTS`, plus Google country domains) drops the item, and other hosts are not classified (partner republication hosts such as yahoo.com articles are labeled `syndicated` instead); a URL is used once across the whole document, and later copies count as duplicates whatever time they report |
| member `published_at` | evidence `published_at` | provider-reported, unverified; must have a time, Z or an offset, and at most millisecond precision |
| member `relation` | Media Lens rule | wire, press-release, or partner host: `syndicated`; otherwise `same_story` |
| `independent_reporting` | none | always empty: text similarity is not evidence of independence |
| `clusters[].origin_claims` | agent `story_origin` via `origin-apply` | labeled `authored_by: ai_agent_via_story_origin_skill`, `verification: unverified`; URLs go through the same public-link policy as members, and any refused URL, URL with a query string or fragment (search terms can name a client), or link on one of six fixed redirector hosts (`t.co`, `bit.ly`, `tinyurl.com`, `ow.ly`, `buff.ly`, `lnkd.in`) is withheld and counted, as is a non-string URL; other redirectors are not recognized; path-style search URLs cannot be recognized in general; origin citations may point at social posts, since a post can be where a story first appeared; a date-only time is kept as a date with `precision: date`, never as midnight; `freshness_status` is Newsjack's own, and `freshness_basis_precision` is Media Lens's reading of the basis value, null when Media Lens would refuse it; origin never changes membership |

Only `news_search` evidence can become a member. Every dropped item is counted on its source row by reason (`incomplete`, `non_https_url`, `non_public_url`, `non_outlet_host`, `duplicate_url`, `title_from_excerpt`, `source_kind_excluded`, `published_at_missing`, `published_at_date_only`, `published_at_precision`, `published_at_unparseable`, `published_at_rolled`, `published_at_after_retrieval`, `outside_window`). The first 200 drops per source are also listed without their URL; the counts always cover every drop. A group with no kept members produces no cluster and is counted in `provenance.clusters_without_members`. Mock and fixture captures are labeled `data_origin: fixture`. For a mock capture, `provenance.binary_check: recorded_in_pin` means only that the capture names a hash recorded in the pin; the runner is what hashed the executed file. A live capture abstains (`newsjack_live_capture_not_supported`), a capture whose detector exit is more than 5 minutes after `now` abstains (`capture_from_future`), a mock capture older than 48 hours abstains (`newsjack_capture_stale`), and an invalid capture abstains with up to 20 error codes and positions. An empty result says `no_results` when Newsjack kept no news-search items after its own age, hygiene, and syndication filters (Newsjack's evidence counts are taken after those filters, so this does not mean the provider returned nothing), `no_accepted_members` when it reported items but none met the member rules or Newsjack emitted none, and `no_member_source_checked` when no member-eligible source was checked (for example, the only source failed). A `--mock` run converts to `empty`, because Newsjack's mock dates carry no time.

The worker's own `influence-graph.v1` schema still lists the removed `artifacts` and `cli` Newsjack modes and the matching provenance values, so the published v1 contract stays unchanged; the worker now emits only `fixture` or `disabled`.

Only public `https` URLs become links. `classifySourceUrl` applies the worker's `parseArticleUrl` policy and refuses names under `NON_PUBLIC_HOST_SUFFIXES` (special-use and private namespaces, wildcard loopback DNS services, and a cloud metadata host). This is a name check, not DNS resolution, which is safe here only because nothing is fetched.

## What is not verified

- The fixtures in `media-lens/fixtures/newsjack-capture/` are hand-written from the pinned source. They were not produced by a Newsjack binary, and no Newsjack binary was built, downloaded, or run for this change. Their key structure, story-size shape, scores, metadata, hygiene reasons, and source status follow v0.1.19 for the default empty profile. Some values are unusual on purpose, to exercise the converter's defensive rules: a URL repeated inside one signal, a `published_at` in the future, a calendar-impossible date, a non-public host, an `http` URL, a URL-like outlet name, and an item just inside Newsjack's own age filter but outside the Media Lens window. v0.1.19 passes each of these through from the provider unchanged. The grouping, the order of evidence inside each signal, and the item count are hand-chosen and would not arise from these texts: the real detector sorts evidence by `published_at` text and groups by snippet similarity (the fixture snippets are placeholder text), and a `quick` run asks the provider for 10 results. `raw-detector-mock-shape.json` and `raw-cluster-mock-shape.json` reproduce the `--mock` output shape and upstream's mock strings; they are not captured output. The source-error pair is a separate run because one query with one source returns either items or an error, never both.
- No live Newsjack run, Medialyst call, feed fetch, or search was made.
- Whether Media Lens may store or show third-party titles, URLs, and times from Medialyst or any other provider.
